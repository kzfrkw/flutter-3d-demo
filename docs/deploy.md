# 公開手順

## 方針

- 依頼者の回答(確認日 2026-10-22): **「D: 当面はサーバに置かない」**。サーバへの配置や、ホスティングの設定はしない。
- 外部への一般公開はしない。
- ブラウザは Chrome(最新版、WebGL2 が有効なもの)。依頼者の回答は「ブラウザは Chrome で」。

このため、ここには「ビルドした成果物を手元で開いて見せる」「フォルダを渡す」手順だけを書く。

## ビルド

```sh
flutter build web --release --no-web-resources-cdn
```

- 成果物は `build/web`(約 47MB)。`index.html`、`flutter_bootstrap.js`、`main.dart.js`、`canvaskit/`、`assets/`(`assets/docs/dev-notes.md` を含む)が入る。
- `--no-web-resources-cdn` を付けると、描画エンジン(CanvasKit)をインターネット(`www.gstatic.com`)から取らず、`build/web/canvaskit/` の同梱ファイルを使う。付けないと、開く側の PC がインターネットに繋がっている必要がある。
- 確認済み: 上のコマンドでビルドが通ること、`--no-web-resources-cdn` の有無で `flutter_bootstrap.js` の `useLocalCanvasKit` が変わること(付けると `true`)。
- 未確認: インターネットに繋がらない PC で Chrome から開いて全画面が正しく表示されること(日本語の文字が出るかを含む)。実装の環境では Chrome を起動できなかった。渡す前に、ネットワークを切った状態で一度確かめることを勧める。

## 見せ方 1: 手元の PC で開く

`build/web/index.html` をダブルクリックして開く(`file://`)と、アセットを読めずに動かない。手元だけで待ち受ける簡易サーバを使う。

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory build/web
```

Chrome で `http://127.0.0.1:8080/` を開く。

- `127.0.0.1` に限定しているので、同じネットワークの他の端末からは見えない。`--bind` を外したり `0.0.0.0` にしたりしない。
- 止めるときは、実行したターミナルで Ctrl+C。
- ビルドをせずに開くだけなら `flutter run -d chrome --release` でもよい(開発用の起動。ビルドの確認はこの方法では足りない)。
- 相手に見せるときは、画面共有を使う。

## 見せ方 2: フォルダを渡す

1. `build/web` を zip にする(例: `cd build && zip -r web.zip web`)。
2. 相手に渡す。相手側でも次が要る。
   - 「見せ方 1」と同じ簡易サーバ(Python 3 など)で待ち受けること。`index.html` のダブルクリックでは動かない。
   - Chrome の最新版で開くこと(WebGL2 が有効であること)。
   - 社外へ転送しないこと。
3. 渡すものにはダミーデータしか入っていない(個人情報・秘密情報はない)。素材のライセンスは `docs/dev-notes.md` の第 6 節。

## 更新と取り下げ

- 更新: コードを直したら、もう一度「ビルド」を実行して `build/web` を作り直す。渡したフォルダは、新しい zip で差し替えてもらう。
- 取り下げ: 手元の待ち受けは Ctrl+C で止める。渡したフォルダは、相手に削除を依頼する。サーバには置いていないので、ほかに取り下げるものはない。

## 付記: URL の開発者用パラメータ

渡す相手に伝えるかは任意。

- `?check`: 技術検証ページ s0-check
- `?people=N`: 人の数(5〜10)
- `?cameraYaw=<度>`: 開始時の視点の向き
